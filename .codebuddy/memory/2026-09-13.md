## 工资报销数据上云（解决换手机数据丢失）
**问题根因**：杂事/工资报销记录只存在本机 storage（key `misc_records_v2`），从未上云，所以换手机/清缓存即丢失。

**方案**（云端为主 + 本机缓存兜底，不频繁请求）：
- 新集合 `misc_record_list`（schema 已建）：type/name/desc/amount/month/createdAt/updatedAt
- 云对象 `waterService` 新增 4 方法：`getMiscRecordList` / `addMiscRecords` / `updateMiscRecord` / `deleteMiscRecord`（+ `sanitizeMiscRecord`、`loadMiscRecords`）
- `common/store.js` 新增 4 个封装并 export（loadMiscRecords/addMiscRecords/updateMiscRecord/deleteMiscRecord）
- `pages/misc-records/misc-records.vue`：
  - `mapCloudRecord`（_id→id）、`buildCloudPayload`、`buildRecordKey`（去重 key）
  - onMounted 同步**一次**（`hasSyncedOnce` 标记防重复请求，失败则允许下次重试）；**双向合并**：云端有→以云端为准，本机独有→自动补传云端（旧手机数据可迁回）
  - 增/改/删改为 await 云端；云端失败降级存本机并提示"已存本机"
- ⚠️ 必须部署才生效：HBuilderX 上传 `waterService` 云函数 + `misc_record_list` schema
- ⚠️ 旧数据只能靠「旧手机再打开一次页面」自动补传；若旧手机本地已清，则无法找回

**踩坑（重要）**：`replace_in_file` 会把**混合行尾文件**（部分 CRLF + 部分 LF）统一成 LF，导致全文件 diff 污染（云对象 417 行、store.js 110 行被重写）。修复法：`git checkout -- 文件` 后用 python 以二进制方式在目标位置插入新代码、沿用该处原有行尾；新增文件无此问题。**改动 CRLF 文件时必须用脚本插入，不要用 replace_in_file。**

## 按人对账备注：非「拉水/回桶」备注显示原文 + 拉水/回桶数据分离
`pages/user-monthly-summary/user-monthly-summary.vue`，只动备注解析 3 个函数，其他未改：
- `detectSingleRemarkType`：无关键词时返回 **null**（原来默认返回'拉水'，导致普通备注被错算成拉水）
- `buildRemarkDiffRecords` 的 `pickValue`：`singleType` 为 null → 返回 0（不参与计算）；写了两个数字仍严格按位置 first=拉水 / second=回桶，两项目不再混用
- `canParseRemarkOrder`：只写一个数字且无「拉水/回桶」关键词 → false（视为普通备注）
- 页面判定链不变：有差值→显示着色段落；能解析且差值全 0→不显示（数据没问题）；其余→显示备注原文
- node 模拟验证 9 种格式全部正确：

  - `拉水 我 100，老大 120` → 拉水差值；`回桶 我 100，老大 120` → 回桶差值（不再串）
  - `老大 0 400，我 0 440` → 回桶差值（0 是占位不计算）
  - `客户说下周送水`/`欠50` → 原文
  - `老大 100 200，我 100 200`（相同）→ 不显示
