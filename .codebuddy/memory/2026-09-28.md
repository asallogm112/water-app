## 付款记录功能（已实现）
**需求**：按人对账里改客户订单的实收金额 = 该客户付款，需留下"谁、何时、改了多少"的流水用于对账（微信/公户转账）。要求 hook 自动记录、**不改动原有逻辑**、UI 与按人对账一模一样、按人对账页加按钮看该客户明细、不要手动补记。

**1) 数据层（云对象 `waterService` + 新集合）**
- 新 schema `uniCloud-aliyun/database/payment_record_list.schema.json`
- 字段：userName / orderId / orderDate / beforeAmount / afterAmount / changeAmount / paidDate / remark / createdAt / updatedAt
- 云对象新增 `PAYMENT_RECORD_COLLECTION` 常量、`sanitizePaymentRecord`、`loadPaymentRecords`、handlers：`getPaymentRecordList`、`deletePaymentRecord`
- **hook 点**：`updateOrder` 内、订单 update 之后 `return` 之前——`beforePayment`(targetOrder.actualAmountReceived) ≠ `afterPayment`(payload.actualAmountReceived) 时插入一条流水，**整段 try/catch**，写失败绝不影响订单更新（严格旁路，未改动原有逻辑）
- 云函数文件是混合行尾，用 python 二进制插入（CRLF 417 保持）；`node --check` 通过

**2) store 层**
- 新增 `loadPaymentRecords()` / `deletePaymentRecord(recordId)` 并导出
- 新增缓存 key `PAYMENT_RECORDS_STORAGE_KEY = 'payment_record_cache'`
- `refreshAll()` 里全量同步付款记录 → 写本机 storage（刷新按钮 = 5 次云调用：userList/orderList/mergeStatus/misc/payment）

**3) 新页面 `pages/payment-records/payment-records.vue`**
- UI 与操作方式**完全照搬按人对账**：客户（上一人/人员弹窗搜索选择/下一人）+ 月份（上一月/月份弹窗/下一月）+ 汇总卡（收款合计/调减合计）+ 明细列表 + 导出 Excel
- 列表按 createdAt 倒序，显示 `+/-¥金额`（绿/红）、客户、订单日期、`¥修改前 → ¥修改后`、备注；每条可删除
- **页面进入只读本机缓存**（遵守零请求红线）

**4) 入口**
- pages.json 注册「付款记录」
- 首页菜单新增 💳「付款记录」（`func-icon-sky`）+ pageMap
- 按人对账客户卡片新增「付款记录」按钮 → 弹窗显示**该客户**的付款明细（同样只读缓存）

**⚠️ 部署要求**：必须上传云函数 `waterService` + `payment_record_list` schema，否则 hook 不生效

**注意**：记录只从功能上线后开始——历史实收金额改动无记录（无法追溯）

## 新需求：付款记录明细（待开发，方案已确认方向）
**用户真实场景**（用户纠正过一次理解）：
- 平时在**按人对账**页修改某客户订单的「实收金额」= 记录该客户付款
- 痛点：改完之后**不知道改了谁、改了多少**，后面对账困难（客户都是微信/公户转账，需核对）
- 因此需要「付款金额变更流水」

**已定方案方向**：
- 记录时机：编辑订单保存时，若 `actualAmountReceived` **发生变化**才记（其他字段变化不记）
- 记录内容：修改时间、客户、订单日期、修改前、修改后、**本次变动（+/-）**、备注
- 查看：新增「付款记录」页（首页入口），按时间倒序，可按客户/月份筛选，汇总本月收款，导出 Excel
- 局限：只能从上线后开始记，历史实收无记录
- **待用户确认**：①是否只记实收金额变化（是）②是否需要"手动补记"入口
