---
name: 每次改完必须说明改了什么
description: 用户要求每次修复/改动后，必须明确告诉他具体改了哪些文件/逻辑，不能只说“已修复”
type: feedback
---

每次改完代码（尤其修复 bug 后），必须明确告诉用户**具体改了什么**：哪个文件、哪段逻辑、为什么这么改、改完验证了什么场景。不能只回「已修复 / 好了」。

**Why:** 用户 2026-10-31 明确指示「每次 改完 之后 , 你必须 告诉我 你改了啥」。他重视可追溯性，之前的回复有时只给结论，他不满。

**How to apply:** 任何代码改动（修复/新功能/配置）完成后，在回复中用简洁列表说明：① 改了哪些文件 + 关键改动点；② 修复/新增的逻辑原因；③ 自测场景与结果。涉及多文件时逐文件点名。若同时更新了记忆文件，也一并说明。
