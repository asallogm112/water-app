description: 用户确认的核心对账设计：付款记录独立存储、绝不修改水单；应收来自水单、实收来自付款、剩=应收−实收
type: feedback
---

**规则/设计原则**：付款记录（payment record）是**独立记录**，与水单（order）分开存储，**绝不修改或覆盖水单本身**。对账时，付款只在水单旁边做「加减」：
- 应收 = 水单数量 × 单价（只来自水单）
- 实收 = 付款金额（只来自付款记录累加）
- 未收/剩 = 应收 − 实收（自动算，不需手填）

典型场景：10月1号水单「拉水200 / 回桶100 / 单价2.2」→ 应收440；再录入 `1001 0 0 220`（10月1号付款220）→ 合计 应收440、实收220、剩220。付款记录不会让水单“显示为已付220”，而是二者并排做加减。

**Why:** 用户 2026-11-02 明确确认「付款是独立记录,只在水单旁边做加减。这句话说对了 我就是 这样设计的 很好」。这是他刻意的设计，不是巧合，且是与我之前的误解（以为付款会去改/标记水单）划清界限。

**How to apply:** 以后任何涉及付款/水单/应收/实收的改动，必须守住这条原则：
1. 付款记录不能去改水单字段，也不能让水单“显示为已付X元” —— 它们是两条独立数据。
2. 应收只能由水单数量×单价得出（付款 quantity=0 → 应收=0，红线，见 `feedback_payment_receivable.md`）。
3. 实收由付款记录累加，剩=应收−实收。
4. 付款记录靠 `createdDate`（如 `1001` 前缀 = 10月1日）与水单在「同一天/同一客户」归集并账；二者必须同一天日期才能合到一起。
