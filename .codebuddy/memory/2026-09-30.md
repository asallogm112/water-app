

## 修复：订单修改金额产生的付款记录时间错误（时区 bug）
**现象**：通过"订单修改金额"（stats / order-list / user-monthly-summary 三处编辑订单）自动生成的付款记录，付款时间比实际晚 8 小时（跨午夜还差一天）；而录入 `0 0 200` 的付款记录时间正确。
**根因**：付款记录显示优先用 `createdAt`。`0 0 200` 路径的 `createdAt` 由客户端 `formatBeijingDateTime(new Date())`（北京时间）传入；而云函数 `updateOrder` 旁路写付款流水时用 `formatDateTime(paymentNow)`——阿里云函数默认 **UTC 时区**，`new Date().getHours()` 是 UTC，导致时间偏差。
**修复**（uniCloud-aliyun/cloudfunctions/waterService/index.obj.js）：
- 新增 `formatBeijingDateTime()`（东八区，用 `getTimezoneOffset` 偏移法，任何环境时区都转北京时间）
- `updateOrder` 付款流水的 `paidDate` / `createdAt` 改用 `formatBeijingDateTime(paymentNow)`
- `createPaymentRecord` 兜底 `createdAt`（未传时）也改用 `formatBeijingDateTime`
- `node --check` 通过，已上传部署到阿里云 water-db-alipay
**注意事项**：本次只修复"之后新生成"的付款记录时间；**历史已存在的错误时间记录不会自动纠正**（需手动删除重录，或后续可写一次性修正脚本，未执行）。
