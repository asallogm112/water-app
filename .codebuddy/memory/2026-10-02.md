# 2026-10-02

## 修复：用户名为「散户」时 应收款 = 实收款 的 bug
- 现象：录入「散户 10 10」并把手填实收改为 0 → 订单显示 应收款 0 / 实收款 0；用户期望应收 = 单价5 × 数量10 = 50
- 根因：`common/utils.js` 的 `getOrderReceivableAmount()` 里有一行硬编码特判 `if (userName === '散户') return getOrderActualReceivedAmount(order)`，导致散户的应收直接等于实收（实收 0 → 应收 0）
- 修复①：删除该特判，散户也走统一逻辑（订单单价 > 客户档案单价 > 未知客户兜底）
- 修复②（同因加固）：`batch-order-add.vue` 的 `updateItemField` 中改数量时原本用 `item.unitPrice`（恒为 0）算 totalAmount → 手改数量会把应收算成 0；新增 `resolveItemUnitPrice(item)`（本行单价 → matchedUserId 对应客户单价 → 按用户名查客户单价）参与计算
- 影响面：`getOrderReceivableAmount` 是 home / order-list / monthly-summary / user-monthly-summary / stats 共用的应收唯一入口，一处修好后全站生效
- 注：`common/utils.js`、`batch-order-add.vue` 为纯 LF 文件，可直接 replace_in_file（务必与 CRLF 的 pages.json / home.vue 区分对待）
